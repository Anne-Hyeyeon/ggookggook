# 1단계 이후 넘긴 일

1단계(콘텐츠와 데이터 구조) 리뷰에서 나왔지만 뒤 단계로 넘긴 항목입니다. 각 단계 계획을 세울 때 이 목록을 먼저 확인합니다.

## 사용자 확인

- 좌표 찍기 도구로 손등 핀과 전신 앞면 부위 점을 직접 확인합니다.
- 실행은 `npm run pin -w @ggookggook/content`입니다. 주소는 http://127.0.0.1:4321 입니다.
- 도구에서 좌우 항목 표시와 클릭 막기는 브라우저로 아직 눌러보지 않았습니다. 확인할 때 같이 봅니다.

## 2단계 (앱)

- 첫 작업으로 TypeScript와 도구 호환을 확인합니다.
- 지금은 TypeScript를 6.0으로 고정했습니다. 7에는 다른 도구가 쓰는 컴파일러 API가 없습니다.
- 내 루틴이 삭제된 혈자리를 가리킬 수 있습니다.
- 앱은 루틴 계산 함수를 부르기 전에 없는 혈자리 단계를 걸러냅니다.
- 계산 함수는 콘텐츠 오류를 드러내려고 계속 예외를 던집니다.
- 가이드 화면에는 위치 설명 한 문장을 보여주기로 했습니다.
- 데이터는 대부분 두 문장입니다. 첫 문장만 쓸지 정합니다.
- 전신 지도의 손목 점과 손 점이 폰 화면에서 약 17px 떨어져 있습니다. 터치 반경을 정할 때 고려합니다.
- 스펙에는 해상도별 이미지 파일을 만든다고 되어 있습니다. 지금은 1024 크기 한 벌뿐입니다. 필요한지 정합니다.

## 3단계 (콘텐츠 배포)

- 빌드를 출시 모드로 검증합니다. 이미지 목록도 함께 넘깁니다.
- 지금은 핀이나 이미지가 빠져도 빌드가 성공합니다.
- 이미 발행한 버전 경로는 덮어쓰지 못하게 막습니다. 오래 캐시되는 경로이기 때문입니다.
- 이전 버전과 비교해서 혈자리 id 삭제를 막습니다.
- manifest에 스키마 버전이나 최소 앱 버전을 넣습니다.
- 빌드 스크립트는 `images/out`이 없으면 그대로 실패합니다. 입력을 먼저 확인하도록 순서를 바꿉니다.
- 고양이처럼 콘텐츠가 아닌 이미지는 번들에서 뺍니다.

## 4단계 (동기화)

- 기록은 추가만 된다고 정했습니다.
- 그런데 기록의 끝난 시각과 피드백이 비어 있을 수 있습니다. 나중에 채우면 수정이 됩니다.
- 설정에는 수정 시각이 없습니다. 나중에 고친 쪽을 남기는 규칙을 쓸 수 없습니다.
- 동기화 설계 때 두 타입을 고칩니다.
- shared 패키지는 import 경로에 확장자를 쓰지 않습니다. infra가 NodeNext 방식을 쓰면 타입 오류가 납니다.

## 콘텐츠 문구

- 폐수, 신수, 명문은 척추뼈를 세어서 찾게 되어 있습니다. 혼자 세기 어려우니 더 쉬운 기준을 덧붙입니다.
- 합곡 문구의 마지막 문장이 규칙과 다릅니다. 출시 전에 한 줄 고칩니다.

## 도구 보강

- 좌표 찍기 서버는 쓰기 실패도 400으로 돌려줍니다. 500으로 바꿉니다.
- 요청 본문 크기 제한이 없습니다. 로컬 전용이라 급하지 않습니다.
- Host 검사가 문자열 그대로 비교합니다. `[::1]` 같은 주소는 막힙니다.
- 배경 제거는 네 모서리 색만 봅니다. 그라데이션 배경에는 약합니다.
- 이미지 테스트는 투명도만 확인하고 색은 확인하지 않습니다.
- 프롬프트 생성기는 데이터를 스키마로 검사하지 않고 읽습니다.
- 검증 스크립트의 경고 라벨이 고정 폭 문자열입니다.
- 검증기는 혈자리 id가 중복되면 마지막 항목으로 임신 검사를 합니다. 중복 자체가 오류라서 급하지 않습니다.
